The showcase terminals use only the public exports of
`@aletheia-works/formicarium`: `createSession` from `/browser`, and
`createCommandSession`, `createInstaller` and `fixtureToFsEntries` from the
package root (the installer quietly installs the tools every page gets, such as
nano, and `fixtureToFsEntries` checks the demo files and home settings the
session starts with). Your page can do the same.

## Requirements

- **Same origin.** The Worker (`runtime/web/package-worker.bundle.js`) and the
  core under `assets/paludarium/` (the loader `index.mjs`, the modules next to
  it, `paludarium.wasm` and `build-info.json`) must be served from your page's
  origin. Without `assets`, the browser entry finds them in the package's own
  layout (the Worker next to it, the core in the package's
  `assets/paludarium/`); to serve them elsewhere on your origin, pass the
  absolute URLs of the Worker, loader, wasm and build information as `assets`.
  The other modules are read next to the loader.
- **Cross-origin isolation.** Serve COOP `same-origin` and COEP `require-corp`,
  or use a service worker such as coi-serviceworker on static hosting.
- **CSP.** Allow same-origin scripts and Workers and WebAssembly compilation,
  for example `script-src 'self' 'wasm-unsafe-eval'; worker-src 'self';
  connect-src 'self'`. `blob:` is not needed. The core is loaded from the asset
  URLs after its digests are checked, so serve them from an origin you trust.
  A page that gives guests a network through a relay also allows the relay's
  `wss:` URL in `connect-src`, and the URL it fetches relay tokens from, if
  any. The showcase terminals add exactly their token function's origin and
  `wss://*.lambda-microvm.ap-northeast-1.on.aws`.
- **Guests.** Use a catalog (`GuestCatalog`) whose entries name each guest's
  HTTPS URL, its SHA256 and its build info. A guest on another origin needs
  CORS. `install <tool>` checks every byte before it registers a guest.
- **Network.** In the browser a guest reaches TCP destinations only through a
  WebSocket relay you name in `network.relay`
  ([command API](/formicarium/guides/command-api/)). The showcase passes
  `network` only to git and jj, with `allow: ['github.com:443']` and the relay
  of a short-lived token from Aletheia Works' token function on AWS, which
  answers only the site's `Origin`. It writes curl's extract of Mozilla's CA
  certificates below the home when the session starts, since the Session takes
  files only then.

## Tools ready from the start

To open a terminal with tools already installed, install them with
`createInstaller` before you create the command session. It runs the same
checks as `install <tool>` but writes nothing, so the user never sees an install
line. An installed tool runs by name in the command session, and every guest
run finds it as `/usr/bin/<tool>`, so one tool can start another (for example a
version control tool that opens an editor). To register guest bytes you already
hold instead of a catalog entry, check them with `validateGuest` and pass the
result to `registerValidatedGuest`.

## Output and display

`CommandSession.execute` returns the original `stdout` and `stderr` bytes of
each command. For a guest run they also arrive in chunks through `onOutput`;
write one or the other, not both. Decode the bytes for display and never treat
them as HTML. `onProgress` reports `totalBytes: null` when the total is unknown,
which differs from `0`. Pass an `AbortSignal` to cancel, and dispose the
session when the page goes away.

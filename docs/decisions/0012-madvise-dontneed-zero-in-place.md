# 0012. madvise(MADV_DONTNEED) では、プライベートな匿名ページをその場でゼロにする

- 状態：採用（2026-10-05）
- 決めた人：ユーザー（不具合の確認と修正を依頼）。実装の方針は開発が決めた

## Context（背景）

blink の `madvise` は、何もせず 0 を返していた。Linux では、プライベートな匿名メモリに `MADV_DONTNEED` をかけると、
次に読んだときゼロになることが保証されている。probe の `madvise-dontneed` は、本物の Linux では合格し、blink では 3 回とも失敗した。

## Decision（決定）

`MADV_DONTNEED` を受けたら、範囲内のプライベートな匿名ページ（`[heap]` と `[stack]` を含む）をその場でゼロにする。
まだ触れていないページ、共有やファイルのマッピングは変えない。整列していないアドレスには `EINVAL`、未割り当ての範囲には
`ENOMEM` を返す。fork のコミット `4b5c67d`。

## Consequences（結果）

- 解放したメモリをゼロ埋め済みとして再利用するアロケータが、正しく動く。
- ほかのスレッドのアドレス変換キャッシュはそのまま有効で、無効化の処理が要らない。
- メモリはホストに返さない（使っていた量のまま）。
- ファイルをコピーしたプライベートなページは、Linux と違い、ファイルの内容に戻らない（未実装）。

## Alternatives Rejected（退けた案）

- **ページを解放して、予約の状態に戻す**：メモリは返せるが、全スレッドのアドレス変換キャッシュの無効化と、
  システムコールが握っているページのロックの扱いが要り、変更が大きくなる。
- **今のまま何もしない**：アロケータが古いデータを「ゼロ埋め済み」として渡す危険が残る。
